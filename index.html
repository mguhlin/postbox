LESS HUNTING. MORE FINDING.

An email archive you can actually use.

01 / READ

Open your exports.

Import EML and Outlook MSG messages, MBOX archives, and Outlook PST mail folders. HTML opens automatically when available, with a plain-text fallback and a green Next button.

02 / FIND

Search with purpose.

Combine from:, to:, cc:, subject:, body:, and has:attachment. Search includes HTML-only message text and attachment filenames.

03 / PREVIEW

See what came with it.

Preview PDFs, photos, audio, and video. Read extracted text from DOCX and supported DOC files. Download the original attachment whenever you need it.

04 / ORGANIZE

Make room for what matters.

Browse year/month groups, select a date range, and export attachments into folders. Export one email or selected emails through a print preview to PDF, with optional clean page formatting. Select multiple messages or attachments for deletion, then advance to the next email.

YOUR FIRST FIVE MINUTES

Keep it local.
Keep it simple.

Once the viewer opens, choose Open managed folder to work with original email files, or import copies to browse.

  1. Choose your archive. Open .eml, .msg, .mbox, .mbx, or .pst exports. Files stay on your computer.
  2. Find a message. Try from:ada has:attachment, or filter by dates and select the matching results.
  3. Save what you need. Export attachments to a chosen folder, organized by year, month, and email.
  4. Close when you’re finished. Close the desktop window to stop its mail engine. For the browser edition, press Ctrl + C in the launcher terminal.

A few useful details.

Which browser should I use?

The Go desktop app uses native file dialogs on all supported systems. In the browser edition, Chrome or Edge supports choosing folders and changing original files. Other modern browsers can read imported copies, delete from the session, and export attachments as a ZIP. PDFs use bundled local PDF.js. Audio/video support depends on system codecs; some PDF variants require another viewer.

What does Delete this email do?

It defaults to This session only and follows the selected deletion mode. Choose original-file editing separately before changing disk files. Original-file deletion removes an EML file or rewrites its MBOX archive; embedded attachments go with the email. Attachment-only deletion rewrites the source email. Session-only deletion leaves files on disk unchanged. Confirmation and original-file checks happen first; separately exported files are never removed. Successful deletion opens the next remaining message. Deletion cannot be undone in Postbox.

Does it upload my email or load trackers?

The app uses a loopback server on your computer. It has no external email service, analytics, or account. Message HTML is sanitized and isolated; scripts, remote images, and navigation are blocked. MBOX and PST parsing briefly use a local temporary file, removed after normal parsing. Clear session discards app records and previews; saved files, printouts and OS/backups remain. See the privacy statement for details.

What are the limits?

PST imports are limited to 2 GB and are streamed through a temporary local file. Other imports are limited to 100 MB. Sessions allow 25,000 messages and 512 MiB of counted session data; peak parser memory may be higher. The desktop Open controls and native file drops stream large PSTs; folder-copy imports are limited to 100 MB in the desktop host. PST originals stay read-only; export selected emails as EML ZIP or MBOX, or delete only from the session. MSG files can be deleted as whole originals, but attachment edits require a session copy or EML export. Contacts and calendar records are not imported. Word previews show text rather than page layout; encrypted and unsupported document variants require another application. Attached-file contents are not indexed by email search.

What has been tested?

Shared MIME/MBOX/Outlook, previews, organizer and print handling have automated regression checks. Native CI builds run synthetic window/file/export checks on Windows, Linux, Apple Silicon and Intel Macs, with actual export-byte verification. Linux also runs with networking disabled. Browser checks cover Chromium/Firefox/WebKit workflows, keyboard navigation, reflow, sandbox behavior and automated accessibility scanning. Native dialogs use test destinations during automation; physical file-picker, screen-reader and system print-dialog checks are separate and remain unverified. Read the VCC review and its limits.
